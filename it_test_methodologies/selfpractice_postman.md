#  Домашняя работа: Установка и знакомство с Postman

**Тема:** Установка Postman и первые шаги в тестировании API

**Цель:** Установить Postman, отправить первый запрос к API и написать простейший тест.

**Время выполнения:** 40–60 минут.

**Оборудование:** Компьютер с Linux (РОСА, Ubuntu, Fedora или любой другой).

---

## Что такое Postman

**Postman** — это программа для отправки HTTP-запросов к серверам и проверки ответов. Она используется для тестирования API (программных интерфейсов) без написания кода. Вы вводите адрес, метод (GET, POST и т.д.), нажимаете «Send» — и видите, что вернул сервер .

**Зачем это нужно:**
- Проверить, работает ли сервер.
- Посмотреть, какие данные отдаёт API.
- Написать автоматические тесты: «ответ должен быть код 200», «в ответе должно быть поле email».

## Часть 1. Установка Postman (20 минут)

### Вариант A. Через Flatpak (рекомендуемый для РОСА)

Flatpak — универсальный способ установки приложений в Linux. Пакет Postman есть на Flathub .

**Шаг 1.** Установите Flatpak и добавьте Flathub:

```bash
sudo dnf install flatpak
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
```

**Шаг 2.** Установите Postman:

```bash
flatpak install flathub com.getpostman.Postman
```

**Шаг 3.** Запустите:

```bash
flatpak run com.getpostman.Postman
```

При первом запуске можно **пропустить** создание аккаунта: нажмите «Skip and go to the app» в левом нижнем углу .

### Вариант B. Через Snap (если установлен snapd)

```bash
sudo snap install postman
```

> ⚠️ **Важно:** Postman официально рекомендует установку через Snap . Однако в некоторых дистрибутивах (например, Ubuntu 22.04+) старые snap-пакеты могут конфликтовать с системными библиотеками. Flatpak надёжнее для РОСА.

### Вариант C. Веб-версия (если установка не удалась)

Откройте в браузере **web.postman.co** и войдите через Google или GitHub. Это полноценная версия, работающая в браузере .

**Задание 1.** Установите Postman любым способом. Запустите и убедитесь, что открывается главное окно.

## Часть 2. Первый запрос (15 минут)

### Что такое API и HTTP-запрос

**API** (Application Programming Interface) — это «дверь», через которую программы общаются друг с другом. Вы отправляете **запрос** — сервер возвращает **ответ**.

**HTTP-методы:**
- **GET** — «дай мне данные».
- **POST** — «создай новую запись».
- **PUT/PATCH** — «измени запись».
- **DELETE** — «удали запись».

### Шаг 1. Откройте новую вкладку

В Postman нажмите **«+»** (или **Ctrl+N**) — откроется пустая вкладка запроса .

### Шаг 2. Введите адрес

В поле URL введите:

```
https://postman-echo.com/get
```

Это тестовый сервер, который просто возвращает то, что вы отправили .

### Шаг 3. Отправьте запрос

Оставьте метод **GET** и нажмите синюю кнопку **«Send»**.

### Шаг 4. Посмотрите ответ

В нижней панели появится ответ сервера в формате **JSON** — это текстовый формат для передачи данных. Вы увидите поля:

```json
{
  "args": {},
  "headers": {
    "host": "postman-echo.com",
    ...
  },
  "url": "https://postman-echo.com/get"
}
```

Также обратите внимание на **код состояния** в правом верхнем углу: **200 OK** — это значит «всё хорошо» .

**Задание 2.** Отправьте запрос на `https://postman-echo.com/get`. Запишите в тетрадь:
- код ответа;
- поле `url` из ответа.

## Часть 3. Сохранение запроса в коллекцию (10 минут)

### Что такое коллекция

**Коллекция** — это папка для запросов. Она помогает организовать работу: например, «Запросы для тестирования магазина» .

### Шаг 1. Сохраните запрос

Нажмите **«Save»** (рядом с «Send»). Postman попросит создать коллекцию.

### Шаг 2. Создайте коллекцию

Назовите её `Мои первые запросы`. Запрос сохранится внутри.

**Задание 3.** Сохраните запрос в коллекцию `Домашняя работа`.

## Часть 4. Первый тест (15 минут)

### Что такое тест в Postman

**Тест** — это проверка, которую Postman выполняет автоматически после получения ответа. Если проверка не проходит — тест «краснеет» .

### Шаг 1. Откройте вкладку Scripts

В вашем запросе перейдите на вкладку **«Scripts»** → **«Post-response»** .

### Шаг 2. Вставьте тест

Нажмите **«Snippets»** (справа внизу) и выберите **«Status code: Code is 200»**. Появится код:

```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});
```

**Разбор кода:**
- `pm.test("название", функция)` — создаёт тест с названием.
- `pm.response.to.have.status(200)` — проверяет, что код ответа равен 200.
- Если код другой — тест **FAIL**, если 200 — **PASS**.

### Шаг 3. Запустите тест

Нажмите **«Send»**. После получения ответа перейдите на вкладку **«Test Results»** — там будет зелёная галочка и надпись **PASS** .

### Шаг 4. Сломайте тест (чтобы проверить, что он работает)

Измените проверку на `status(404)`:

```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(404);
});
```

Нажмите **«Send»**. Теперь тест должен **провалиться** (красный). Это доказывает, что тест реально проверяет код ответа.

Верните `status(200)` обратно.

**Задание 4.** Добавьте второй тест: проверьте, что ответ содержит поле `url`.

Подсказка:

```javascript
pm.test("В ответе есть url", function () {
    const body = pm.response.json();
    pm.expect(body.url).to.be.a('string');
});
```

## Частые проблемы

| Проблема | Решение |
|---|---|
| Postman не запускается | Попробуйте веб-версию: web.postman.co |
| Не находит команду `flatpak` | Установите: `sudo dnf install flatpak` |
| Ошибка «No such file» при `flatpak run` | Проверьте: `flatpak list | grep -i postman` |
| Запрос висит без ответа | Проверьте интернет-соединение |

## Дополнительно (по желанию)

Если хотите пойти дальше — создайте **переменную окружения** для базового URL:

1. В левой панели нажмите **«Environments»** → **«+»**.
2. Создайте окружение `Тест` с переменной `base_url` = `https://postman-echo.com`.
3. В запросе используйте `{{base_url}}/get` вместо полного адреса.

Это удобно: при смене сервера вы меняете адрес в одном месте, а не в каждом запросе .
